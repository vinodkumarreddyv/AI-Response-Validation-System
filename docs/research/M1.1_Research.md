# M1.1 — Research & Technical Understanding

## 1. Introduction

The AI Response Validation System is designed to evaluate AI-generated answers and identify responses that are correct, partially correct, incorrect, or unsupported by available knowledge.

The system combines reference-answer comparison, knowledge-base retrieval, semantic similarity, factual checking, contradiction detection, and rule-based scoring to produce an evaluation result.

The purpose of Milestone 1 is to establish the research foundation and technical approach for the complete AI response evaluation system.

---

## 2. LLM Evaluation

Large Language Model (LLM) evaluation is the process of measuring the quality, correctness, relevance, reliability, and usefulness of responses generated by an AI model.

A response should be evaluated using multiple dimensions rather than relying only on exact string matching.

Important evaluation dimensions include:

- Relevance
- Accuracy
- Factuality
- Faithfulness
- Hallucination
- Completeness
- Semantic similarity
- Consistency

For this project, the primary objective is to determine whether an AI-generated response correctly answers the submitted question and whether the response is supported by the available reference answer and retrieved knowledge.

---

## 3. Automated AI Response Evaluation

Automated evaluation allows AI-generated responses to be assessed without manually checking every response.

A typical automated evaluation workflow contains:

1. Receive the user question.
2. Receive the AI-generated response.
3. Optionally receive a reference answer or source material.
4. Retrieve relevant knowledge from a reference knowledge base.
5. Compare the response with the reference information.
6. Calculate evaluation signals.
7. Detect factual matches and contradictions.
8. Produce dimension-level scores.
9. Generate a final verdict.

Automated evaluation should combine several signals because no single metric is reliable for every type of response.

For example, semantic similarity can identify equivalent wording, while direct fact checking can provide stronger evidence for simple factual questions.

---

## 4. Relevance

Relevance measures whether the AI response addresses the user's question.

A relevant response should:

- Directly address the question.
- Contain information related to the requested topic.
- Avoid unrelated information.
- Focus on the expected subject.
- Provide information useful for answering the question.

In a retrieval-based evaluation system, relevance can also be considered when selecting evidence from the knowledge base.

The project uses question-based retrieval and relevance-related scores to identify information useful for evaluating the response.

---

## 5. Accuracy and Factuality

Accuracy measures whether the information provided by the AI response is correct.

Factuality focuses specifically on whether the claims made by the response are supported by reliable information.

### Example

Question:

> What is the capital of France?

Reference answer:

> Paris

AI response:

> The capital of France is Paris.

The response is factually correct.

However:

> The capital of France is Berlin.

is factually incorrect.

The system uses reference-answer comparison, semantic similarity, direct fact matching, and direct contradiction detection to identify such cases.

---

## 6. Hallucination Detection

Hallucination occurs when an AI system generates information that is unsupported, fabricated, or inconsistent with reliable information.

Examples include:

- Invented facts
- Incorrect names
- Incorrect dates
- Unsupported claims
- Fabricated explanations
- Contradictions with reference knowledge

For a RAG-grounded evaluation system, hallucination detection can use retrieved evidence as a source of supporting information.

Important signals include:

- Reference similarity
- Evidence similarity
- Direct fact contradiction
- Contradiction detection
- Entailment
- Neutrality
- Evidence support

The current Milestone 1 implementation uses direct contradiction checks and evidence comparison as important baseline signals.

---

## 7. Faithfulness

Faithfulness measures whether an AI response is supported by the provided source or retrieved context.

A faithful response should not introduce claims that cannot be supported by the available evidence.

For a RAG-based evaluation system, retrieved knowledge is important because it provides evidence that can be compared with the generated response.

For example, if the retrieved source states:

> Paris is the capital of France.

then a response stating:

> Paris is the capital of France.

is supported by the evidence.

If the response introduces an unrelated unsupported fact, its faithfulness may be lower.

---

## 8. Completeness

Completeness measures whether the response contains the important information required to answer the question.

A response can be factually correct but incomplete.

### Example

Question:

> What are the two major types of memory discussed in the source?

Response:

> Semantic memory.

If the source expects both semantic and episodic memory, the response is incomplete even though the information provided is correct.

Completeness can therefore be evaluated by comparing the response with the expected reference information and identifying whether important answer components are missing.

---

## 9. Semantic Similarity

Semantic similarity measures how closely two pieces of text are related in meaning.

Unlike exact string matching, semantic similarity can recognize responses that use different wording but express similar information.

The project uses the `all-MiniLM-L6-v2` sentence-transformer model to generate embeddings.

The generated embeddings are normalized and compared using cosine similarity.

A cosine similarity value closer to 1 indicates stronger semantic similarity, while a value closer to 0 indicates weaker similarity.

Semantic similarity is used for:

- Comparing an AI response with a reference answer.
- Comparing an AI response with retrieved evidence.
- Supporting retrieval ranking.
- Providing a fallback evaluation signal.

Semantic similarity alone is not treated as proof of factual correctness because semantically related text can still contain incorrect information.

---

## 10. RAG Architecture

Retrieval-Augmented Generation (RAG) combines information retrieval with language-model generation.

A typical RAG pipeline contains:

1. User question
2. Query processing
3. Knowledge-base retrieval
4. Relevant document/chunk selection
5. Context preparation
6. AI response generation
7. Response evaluation

For this project, RAG concepts are used primarily for evaluation.

The submitted question is used to retrieve relevant knowledge-base chunks. These chunks are then supplied to the validation process as evidence.

The system therefore uses retrieval to provide supporting information for response evaluation.

---

The retrieval pipeline implemented in this project follows this general flow:


The retrieval process uses the same embedding model used to create the knowledge-base embeddings.

The query is converted into an embedding and compared against indexed knowledge-base vectors.

The most relevant chunks are returned as retrieved evidence.

---

## 12. Embeddings

An embedding is a numerical representation of text in a vector space.

Text with similar meaning tends to have embeddings that are closer together.

The project uses:

```text
Model: all-MiniLM-L6-v2
Embedding dimension: 384
```

The model is provided through the Sentence Transformers library.

Knowledge-base chunks are converted into embeddings and stored as NumPy arrays before being indexed in FAISS.

Embeddings enable semantic search rather than simple keyword-only matching.

---

## 13. Vector Search

Vector search finds the most semantically similar items to a query by comparing vector representations.

The project uses FAISS for vector search.

The knowledge base contains embeddings for:

- TruthfulQA
- SQuAD training data
- SQuAD validation data

The combined FAISS index contains:

```text
Total vectors: 99,024
Embedding dimension: 384
```

The vector store is used to retrieve evidence relevant to a submitted evaluation question.

## 15. LLM-as-a-Judge

LLM-as-a-Judge is an evaluation approach in which a language model is used to evaluate another AI-generated response.

Instead of relying only on exact matching, an evaluator model can assess a response according to a defined rubric.

Typical evaluation inputs include:

- User question
- AI-generated response
- Reference answer
- Retrieved evidence or source context
- Evaluation criteria

An LLM judge can produce:

- A numerical score
- A categorical verdict
- An explanation
- Dimension-specific scores

For this project, LLM-as-a-Judge is considered as an advanced evaluation capability for assessing relevance, accuracy, completeness, faithfulness, and other complex response properties.

The current Milestone 1 implementation primarily uses deterministic and embedding-based validation techniques. This provides a transparent baseline before introducing more advanced LLM-based judge agents.

A judge-based evaluation system should itself be validated because an LLM evaluator can make inconsistent or incorrect judgments.

## 16. Evaluation Frameworks

### 16.1 RAGAS

RAGAS is an evaluation framework designed for evaluating Retrieval-Augmented Generation systems.

Relevant RAGAS evaluation concepts include:

- Faithfulness
- Answer relevance
- Context relevance
- Context precision
- Context recall

These metrics help evaluate different parts of a RAG pipeline.

For example:

- Answer relevance measures whether the generated answer addresses the question.
- Faithfulness measures whether the answer is supported by retrieved context.
- Context relevance measures whether the retrieved information is useful for the question.
- Context precision evaluates the quality of retrieved context.
- Context recall evaluates whether relevant information was successfully retrieved.

RAGAS was studied because its evaluation concepts align with the goals of this project.

The project does not make RAGAS a mandatory runtime dependency for Milestone 1. Instead, the framework is used as a reference when defining evaluation dimensions and scoring methodology.

### 16.2 TruLens

TruLens is an evaluation framework for LLM applications that provides programmatic feedback functions for evaluating application runs.

TruLens supports evaluation approaches including:

- Ground-truth evaluation
- Human feedback
- Traditional NLP metrics
- Model-based evaluation
- LLM-based evaluation

For RAG applications, TruLens provides evaluation concepts such as:

- Context relevance
- Answer relevance
- Groundedness
- Comprehensiveness

TruLens was studied because its evaluation approach aligns with the proposed agent-based evaluation architecture.

The current Milestone 1 implementation does not directly depend on TruLens. Instead, the project implements its own validation pipeline so that individual scoring signals can be inspected and controlled.

## 18. Evaluation Scoring Methodology

The system combines multiple signals rather than relying on a single similarity value.

The main evaluation signals are:

### 18.1 Reference Similarity

Measures semantic similarity between the AI response and the trusted reference answer using sentence embeddings.

### 18.2 Evidence Similarity

Measures semantic similarity between the AI response and retrieved knowledge-base evidence.

### 18.3 Direct Fact Matching

Checks whether an expected fact is explicitly present in the response.

### 18.4 Direct Fact Contradiction

Checks whether the response contradicts an expected fact.

### 18.5 Relevance

Measures how strongly retrieved evidence relates to the submitted question and response.

### 18.6 Exact Match

Identifies whether a retrieved evidence item directly contains the expected fact or answer.

These signals are combined to produce a final evaluation score and verdict.

---

## 19. Current Rule-Based Validation

The current validation service uses explicit rules for simple factual questions.

For a capital-city question, for example:

```text
Question:
What is the capital of France?

Expected fact:
Paris

Correct:
The capital of France is Paris.

Incorrect:
The capital of France is Berlin.
```

The validation process distinguishes:

- Direct correct answers
- Direct contradictions
- Responses that contain the expected fact without directly answering
- Responses requiring semantic fallback evaluation

This provides a deterministic baseline for factual evaluation.

---

## 20. Evaluation Score

The system uses a normalized score between 0 and 1.

The current interpretation is:

| Score Range | Interpretation |
|---|---|
| 0.75 – 1.00 | Correct |
| 0.50 – 0.74 | Partially Correct |
| 0.00 – 0.49 | Incorrect |

The current implementation also applies stronger rules for direct factual matches and contradictions.

A direct contradiction receives a low score because it provides strong evidence that the response is wrong.

A direct factual match receives a high score because it provides strong evidence that the response correctly answers the question.

A response containing the expected fact without directly answering the question may be classified as partially correct.

Semantic similarity and evidence similarity are used as fallback signals when deterministic fact checking cannot make a final decision.

The thresholds can be adjusted during later benchmark evaluation.

## 31. Proposed Agent-Based Evaluation Architecture

The proposed evaluation architecture separates the evaluation responsibilities into specialized components.

The planned components are:

- Evaluation Orchestrator
- Relevance Judge Agent
- Accuracy Judge Agent
- Hallucination Detection Agent
- Completeness Judge Agent
- Verdict Agent

The Evaluation Orchestrator coordinates the evaluation flow.

The Relevance Judge Agent evaluates whether the response addresses the question.

The Accuracy Judge Agent evaluates factual correctness against reference information.

The Hallucination Detection Agent identifies unsupported or contradictory claims.

The Completeness Judge Agent evaluates whether important answer information is present.

The Verdict Agent combines the evaluation outputs and produces the final verdict.

This separation makes the architecture modular and allows individual evaluation components to be improved independently.

## 35. Limitations and Future Improvements

The Milestone 1 implementation provides a foundation rather than a complete production-grade evaluation platform.

Current limitations include:

- Rule-based factual checking is strongest for structured/simple factual questions.
- Semantic similarity does not guarantee factual correctness.
- LLM-as-a-Judge is not yet the primary runtime evaluator.
- Completeness evaluation can require deeper answer decomposition for complex questions.
- Retrieval quality depends on the quality and coverage of the knowledge base.
- Current benchmark ingestion uses JSON files and a local FAISS index.
- Evaluation thresholds may require calibration against labelled benchmark examples.

Future improvements can include:

- Advanced LLM judge agents.
- Claim-level factuality analysis.
- More robust contradiction detection.
- Improved completeness scoring.
- Human evaluation comparison.
- Benchmark-based threshold calibration.
- Additional QA and factuality datasets.
- Batch evaluation.
- Evaluation reports and analytics.

---

## 36. Conclusion

The research establishes that reliable AI response evaluation should use multiple complementary signals.

Exact string matching alone is insufficient because a correct response may use different wording from the reference answer.

Semantic similarity improves flexibility but can incorrectly consider related information to be correct.

Retrieval provides external evidence that can be used to assess whether an AI response is supported by available knowledge.

Direct factual checking provides stronger signals for simple factual questions.

LLM-as-a-Judge can provide flexible evaluation for complex responses, but the evaluator itself must be validated.

RAGAS and TruLens provide useful reference frameworks for understanding evaluation dimensions and RAG evaluation workflows.

Based on this research, the project uses a hybrid evaluation strategy combining:

- Reference-answer comparison
- Semantic similarity
- Knowledge-base retrieval
- Evidence similarity
- Direct fact matching
- Contradiction detection
- Rule-based scoring

This forms the technical foundation for the system architecture, evaluation input module, and reference knowledge base implemented during Milestone 1.
