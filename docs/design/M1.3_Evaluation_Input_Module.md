# M1.3 — Evaluation Input Module

## 1. Purpose

The Evaluation Input Module is the entry point of the AI Response Validation System.

It provides a single submission interface where a user can submit:

- The question asked to the AI
- The AI-generated response
- An optional trusted/reference answer
- Optional retrieved/source/reference material

The module validates the input and sends the evaluation request through the backend/API layer for processing.

---

## 3. User Interface

The interface contains two primary areas.

### Response Input

The user enters:

1. Question
2. AI Response
3. Reference Answer (optional)
4. Retrieved Evidence / Source Material (optional)

### Validation Result

After submission, the interface displays:

- Final score
- Verdict
- Reference similarity
- Best evidence similarity
- Expected fact
- Contradiction status
- Direct fact match
- Direct contradiction
- Reference exact match
- Evidence details


## 8. API Contract

The evaluation submission endpoint is:

```text
POST /api/evaluation/submit
```

The endpoint receives an evaluation request and returns a structured evaluation result.

Example request:

```json
{
  "question": "What is the capital of France?",
  "ai_response": "Paris",
  "reference_answer": "Paris",
  "evidence": [
    {
      "text": "Paris is the capital of France.",
      "distance": 0.1,
      "index": 1
    }
  ]
}
```

Example response:

```json
{
  "validation": {
    "score": 1.0,
    "verdict": "CORRECT",
    "reference_similarity": 1.0,
    "reference_exact_match": true,
    "expected_fact": "paris",
    "direct_fact_match": true,
    "direct_fact_contradiction": false
  }
}
```

## 9. Error Handling

The module should handle the following cases.

### Missing question

Expected behavior:

```text
Question is required.
```

### Missing AI response

Expected behavior:

```text
AI response is required.
```

### Empty submission

The request should not be sent to the evaluation engine.

### Backend unavailable

The frontend should display a user-friendly message such as:

```text
Unable to connect to the evaluation service.
Please make sure the backend is running.
```

### Invalid API response

The frontend should avoid crashing and display an appropriate error message.

---

## 10. Optional Reference Answer Behavior

The reference answer is not mandatory.

When provided:

```text
AI response
      |
      +---- Reference comparison
      |
      +---- Direct fact checking
      |
      +---- Semantic similarity
```

When not provided:

```text
AI response
      |
      +---- Knowledge retrieval
      |
      +---- Evidence similarity
      |
      +---- Other available checks
```

This allows the system to support both reference-based and evidence-based evaluation.

---

## 11. Optional Source Material Behavior

The source/reference material can provide additional evidence for evaluation.

The logical flow is:

```text
Source Material
      |
      v
Processing / Chunking
      |
      v
Evidence
      |
      v
Validation
```

When no source material is provided, the system can use the configured reference knowledge base.

## 13. Result Presentation

The result dashboard should clearly communicate the evaluation outcome.

### Verdict

Possible primary verdicts:

```text
CORRECT
PARTIALLY CORRECT
INCORRECT
```

### Score

The numeric score is normalized between:

```text
0.0 and 1.0
```

The frontend may display it as a percentage.

Example:

```text
0.85 -> 85
```

### Supporting indicators

The result may include:

```text
Reference Similarity
Best Evidence Similarity
Expected Fact
Contradiction
Direct Fact Match
Direct Contradiction
Reference Exact Match
```

## 17. M1.3 Completion Summary

The Evaluation Input Module provides the foundation for the complete evaluation pipeline.

It accepts the required evaluation information, supports optional reference/evidence information, validates the submission, communicates with the backend, and presents the structured evaluation result.

This module is intentionally kept separate from the evaluation logic so that the evaluation agents and knowledge-base retrieval system can evolve independently in later milestones.
